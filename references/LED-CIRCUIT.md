# ALIENTEK 精英 STM32F103 V1 onboard LED and key wiring

This project uses the **ALIENTEK 精英 STM32F103 V1.0** wiring documented in
the local author manual:

`references/STM32F1开发指南_精英板_寄存器版_V1.0.pdf`

The SHA-256 of the reference PDF is
`202e31e4952e5ee2cd5fc5f1dd641626ffaa0a205c2fe5f3b141920b37a5eeb2`.

## LED wiring

| Board item | MCU pin | Electrical path | GPIO meaning |
| --- | --- | --- | --- |
| LED0 / DS0, red | PB5 | `3V3 → R15 510 Ω → LED0 anode; LED0 cathode → PB5` | LOW = on, HIGH = off |
| LED1 / DS1, green | PE5 | `3V3 → R19 510 Ω → LED1 anode; LED1 cathode → PE5` | LOW = on, HIGH = off |

The manual’s LED schematic is Figure 2.1.17.1 on PDF page 39 (printed page
26). The paragraph immediately below the figure identifies LED0/DS0 as PB5
and LED1/DS1 as PE5. The output example on PDF pages 118–119 (printed pages
105–106) initializes both pins HIGH and then uses `LED0=0` to light DS0;
this confirms the active-low polarity. The same example’s `LED_Init` sets
PB5 and PE5 to push-pull outputs and defaults them HIGH.

`examples/breathe.c` uses those physical connections directly. Its software
PWM writes the STM32 GPIO `BSRR` lower half to set HIGH (LED off) and upper
half to reset LOW (LED on), and the simulator records the resulting PB5/PE5
transitions as the brightness trace.

## On-board key wiring

| Board key | MCU pin | Idle wiring | Active level |
| --- | --- | --- | --- |
| KEY_UP / WK_UP | PA0 | switch to 3.3 V | HIGH |
| KEY0 | PE4 | switch to GND; use the MCU internal pull-up | LOW |
| KEY1 | PE3 | switch to GND; use the MCU internal pull-up | LOW |

The key schematic is Figure 2.1.18.1 on PDF page 39 (printed page 26). The
manual states that KEY0/KEY1 are on PE4/PE3 and use internal pull-ups, while
KEY_UP is on PA0/WK_UP and is high-level triggered. The consolidated GPIO
table gives the same mapping on PDF pages 12–14 (printed pages 12–14), and
the key experiment repeats the active-level rule on PDF page 132 (printed
page 119).

## Trace contract for the renderer

The firmware runner emits ordinary GPIO edge events. For either LED channel,
`value: 0` is the light-on interval and `value: 1` is the light-off interval.
The renderer must calculate duty from the measured low-time in each 10 ms
frame, then display the two real onboard channels independently:

```text
PB5 → LED0/DS0 (red), activeLow=true
PE5 → LED1/DS1 (green), activeLow=true
```

No brightness value is generated by the UI or substituted for a missing
firmware event; it is derived from the ARM ELF GPIO trace.
