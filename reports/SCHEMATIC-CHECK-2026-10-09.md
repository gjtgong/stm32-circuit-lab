# 原理图与 PCB 网络交叉核查（实验性）

输入为本地获取的 PE.JADO EasyEDA Standard 原理图与 PCB 源文件，没有修改来源文件。解析依据 [官方格式说明](https://docs.easyeda.com/en/DocumentFormat/2-EasyEDA-Schematic-File-Format/)。

| 项目 | 结果 |
|---|---:|
| 原理图引脚 | 366 |
| 匹配 PCB 端子 | 364 |
| 匹配端子的网络分组差异 | 0 |
| NC 标记连接异常 | 0 |
| 原理图明确 NC、PCB 无网络端子 | 6 |
| 未匹配 PCB 位号的原理图端子 | 2 |
| 缺少元件引用的 PCB 焊盘 | 16 |
| 共用连接的多标签组 | 3 |

6 个明确 NC 端子与源标记如下：

| 端子 | 原理图引脚名称 | NC 标记 ID |
|---|---|---|
| U2:106 | NC | gge7516 |
| USB1:2 | D- | gge16640 |
| USB1:3 | D+ | gge16642 |
| USB1:4 | ID | gge9935 |
| SW1:1 | 1 | gge13804 |
| SW1:4 | 4 | gge13806 |

U2:106 的标记位于接出的导线短桩末端，检查器沿真实导线识别，不只比较标记与引脚坐标。NC 与其他引脚或命名网络相连时会报标记异常，不能用 NC 掩盖真实连接。

原理图 BOOT1 与 PCB BOOT 的源元件 ID 同为 gge6179817c66a49e90，据此匹配；没有按相似位号或网络名猜测。X1:1、X1:2 未找到带相应元件引用的 PCB 端子，不能据此认定晶振缺失：PCB 中仍有16个缺少引用的焊盘，需要恢复源身份后继续核查。

多标签组为 PA13/SWDIO、PA14/SWCLK、BOOT1/PB2。同一连接可以有别名，本工具保留全部标签并要求复核，不自动认定这些组电气正确。

连接图覆盖 504 条导线段、286 个网络/电源标签和6个 NC 标记。明确连接锚点包括导线顶点、引脚连接点、标签连接点和 J 连接点；不创建任意内部交叉点。只处理单页直线导线；总线、层级和未识别记录拒绝解析。比较的是源 PCB 已分配网络，而非铜是否真的连通，应与 Gerber 检查一起使用。

17项核对测试通过，包含无标记交叉与明确连接点、T连接、远端同名标签、NC 短桩、NC 误接、总线拒绝、PCB 网络拆分/合并、重复焊盘网络冲突、元件 ID 位号映射，以及真实板网络修改与真实 NC 标记删除的内存故障注入。详细报告运行 `python3 tools/schematic_check.py` 生成到 reports/schematic-check.json；API 校验原理图及 PCB 源 SHA256 后才提供报告。

结论限于匹配端子的一致性与源 NC 意图。未验证厂商引脚要求、驱动能力、电源电压、电流、温度、实际生产可用性，也不声明整板通过 ERC/DRC。
